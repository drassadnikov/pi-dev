Перемещение/переименование: `move path="старый" to="новый"` (path= работает и для файлов без .md).

# Тест-кейсы (RUPU/PPTM, JSON-массив)
- Данные в шагах внутри <pre><code> — СТРОГО pretty JSON: каждый ключ с новой строки, отступ 4 пробела, строки в двойных кавычках (внутри JSON-полей экранированы как \"), переносы внутри JSON-поля — как \n; компактный однострочный JSON запрещён.
- Названия — БЕЗ префиксов [ПРАВИЛО_NNN]: начинаются с «Позитивный сценарий:» / «Негативный сценарий:» / «Интеграционный сценарий:». Итоговый JSON-массив — в отдельный .json-файл (test-cases.json) в папке проекта: только сам массив, без markdown.
- Рисунки (скриншоты/экраны) — БЕЗ подписей-капшен: «Экран (из ТЗ):», «Рис. 1.» и любые другие подписи перед <img> запрещены, только сам тег <img .../>.
- В шагах ОБЯЗАТЕЛЬНО: сервис-инициатор → сервис, в котором вызывается метод, → метод URL (формат Кибаны): «Вызов: <code>Сервис-инициатор → сервис-приёмник: METHOD /url</code>» (напр. «Яндекс WebView SDK → rpup-delivery-adapter: POST /delivery/address/validate», «rpup-operations → rpup-yandex-profile: POST /v1/consents/url»). Строк «URL: <code>...</code>» без сервисов быть не должно.
- В описаниях (description, name) НЕ ссылаться на названия источников: без «по схеме ...drawio», «из ТЗ ...docx», «соответствует ТЗ» — только суть сценария.
- Тестовые данные согласованы: если сценарий по Санкт-Петербургу, в fullAddress ответа — «г. Санкт-Петербург», а не «г. Москва».
